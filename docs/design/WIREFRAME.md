## Overview

**한사나다는 강원도 18개 시·군의 관광지를 지도로 발견하고, 각 장소의 향후 30일 중 상대적으로 한산한 날을 골라, 로그인 없이 개인 컬렉션에 모아두는 모바일 우선 반응형 웹이다.**

**핵심 사용자.** 강원도로 떠나기 전 휴대폰으로 후보를 추리는 사람. 계정이 없고, 만들 생각도 없다. `온라인 언급량`·`기준 시점` 같은 말을 모르고 알 필요도 없다.

**상위 과업 (JTBD).**
> "강원도에 가고 싶다. 유명한 데는 붐빌 것 같고, 안 붐비는 데는 어딘지 모르겠다. **갈 만한 장소 몇 곳과 언제 갈지를 정해서, 잊어버리기 전에 모아두고 싶다.**"

이 과업이 구조를 지배하는 방식은 하나다 — **화면은 장소를 평가해 주지 않고, 사용자가 스스로 좁혀 나가게 한다.** DESIGN.md의 시금석("굵은 글씨가 장소를 평가하나, 데이터를 진술하나")이 배치에서는 이렇게 번역된다: 어떤 화면도 "여기로 가세요"라는 단일 결론을 내지 않고, **범위를 좁히는 도구와 그 근거를 같이 놓는다.**

**이번 패스 미사용 컴포넌트: 없음.** DESIGN.md의 48개 컴포넌트가 전부 어딘가에 배치됐다(§커버리지 참조).

## User Flows

동적 화면이라 wireflow(와이어프레임 + 흐름 화살표)로 문서화한다. 화살표 뒤 괄호는 그 스텝에서 바뀌는 상태다.

**F1 — 무테마 발견** (사용자 스토리 1·2)
```
탐색 홈 진입
  → [지도] 18개 시·군 방문 규모 색 비교 (시트: 중간 스냅, 카드 2~3장 보임)
  → 시·군 탭 또는 지도 이동 → [region-search-button 이 지도 영역에서 검색] (목록 범위 갱신)
  → [시트 헤더] 온라인 언급 많은 순 ⇄ 온라인 언급 적은 순 전환 (정렬 반전 · 정보 없음 구간은 하단 고정)
  → 카드 탭 → 관광지 상세
```

**F2 — 테마 · 검색으로 좁히기** (사용자 스토리 3)
```
탐색 홈 → [search-field] 탭 → 검색 시트
  ├ 지원 테마 칩 선택 (벚꽃 등 8개)      → 결과: 지원 테마 (추천 자격·큐레이션 통과)
  └ 자유 입력 → 지원 테마로 정규화되면 그 사실을 문장으로 알림
                 정규화 실패 → 결과: 일반 검색 ([general-search-notice] 상단 고정)
  → 카드 탭 → 관광지 상세
```

**F3 — 날짜로 좁히기** (사용자 스토리 4·5)
```
탐색 홈 → [조건 요약 줄의 날짜] 탭 → 날짜 시트
  ├ `날짜가 정해졌어요` → 30일 캘린더에서 하루 선택 (30일 밖은 비활성)
  │     → 카드에 [crowd-badge] `이 장소 기준 한산/보통/혼잡`
  └ `한산한 날에 갈래요`
        → 카드에 [quiet-date-value] 장소별 한산 예상일
  → 카드 탭 → 상세에서 30일 예측 전체 확인
```

**F4 — 검토 → 저장 → 다시 보기** (사용자 스토리 6·7)
```
관광지 상세
  → 기본정보 → 언제 갈까요(30일 예측) → 지금 가는 길(도로·주차) → 대신 가볼 만한 곳 → 함께 가기 좋은 곳
  → [button-primary 저장하기] → 저장 편집 시트 (태그·메모·방문 예정일)
  → 저장 완료 → 같은 자리 버튼이 [저장됨 · 나만의 지도에서 보기]로 전환 (별도 토스트 없음)
  → 나만의 지도 → 저장 장소만 지도+목록 → 카드 탭 → 상세(최신 정보 재조회)
```

## Per-Page Layout

### 탐색 홈 `/`

**목적 / 핵심 과업.** 지도로 지역을 비교해 범위를 정하고, 그 범위 안 관광지를 훑어 상세로 들어갈 후보를 고른다.

**존 구조 (모바일 · 우선순위 순)**

1. **지도 (전면)** — 화면 전체. `map-region-fill-1..4` 면, `map-region-outline` 경계, `map-region-fill-nodata` 사선 해칭, `map-place-label` 흰 알약 마커 라벨.
2. **상단 컴팩트 바 (지도 위 플로팅)** — `search-field` 축약형 + **조건 요약 줄**. 조건 요약은 가로 스크롤 칩 열이다: `강원 전체` `무테마` `날짜 미정` `온라인 언급 많은 순` — 각각 탭하면 해당 시트가 열리고, 끝에 `[초기화]`.
3. **지도 위 액션** — `region-search-button` (지도를 움직인 뒤에만 등장, 지도 상단 중앙).
4. **범례** — `map-legend`. 지도 영역 좌하단, **시트 바로 위에 붙어 따라 올라간다**(시트에 가리지 않는다). 색 구간 · 사선(정보 없음) · 기준 기간 · 출처. **접히지 않는다.**
5. **목록 바텀시트** — 세 스냅: `접힘(peek)` 헤더만 / **`중간` 화면의 55% = 첫 진입 기본** / `펼침` 상단 여백만 남김.
   - 시트 헤더: 핸들 · `section-heading` "이 지도 범위 N곳" · `sort-toggle-item` / `-selected`(`온라인 언급 많은 순` / `온라인 언급 적은 순`)
   - 헤더 하단 고정 `data-source-note`: **기준 시점 한 줄**. 공급자 이름도 해명 문장도 싣지 않는다 — 정렬 라벨이 이미 무엇을 센 값인지 말한다. 정렬이 적용되지 않았으면 그 사실을 먼저 한 줄로 밝힌다("지금은 온라인 언급 정보가 없어 순서를 매기지 않았어요")
   - 본문: `place-card` 반복 → (`divider`) → **`온라인 언급 정보 없음 N곳` 구간**
6. **하단 내비** — `bottom-nav-item` / `-active` + `saved-count-badge`. **시트 위에 항상 뜬다**, 시트 콘텐츠 하단에 내비 높이만큼 여백.

### 관광지 상세 `/places/:id`

**목적 / 핵심 과업.** 다섯 종류의 정보를 **섞이지 않게** 확인하고 저장할지 정한다.

**존 구조 (위→아래 · 섹션 사이 `section-gap` 48px)**

1. 상단 고정 바 — `[← 뒤로]`(H3 비상구). 스크롤하면 관광지 이름이 축약돼 따라온다.
2. 사진 (16:9) → `place-detail-title` (말줄임 없음) → `place-card-meta` 주소·분류 → `data-source-note`
3. **언제 갈까요** — `section-heading` / 날짜 모드 탭 / 30일 예측 / `crowd-badge-*` 또는 `quiet-date-value` / `data-source-note` **"이 장소 자체 기준"**
4. **지금 가는 길** — `section-heading` / `road-status-dot-smooth|slow|jam` + `place-detail-body` 라벨 / 주차 잔여면 또는 `no-data-badge` / `data-source-note` 조회 시각 · 출처 · **"미래 날짜 인파와 다른 정보"**
5. **대신 가볼 만한 곳** — `place-card` 가로 스크롤. 추천 자격을 통과한 **관광지만**
6. **함께 가기 좋은 곳** — `place-card` 가로 스크롤. 음식점·숙박. **같은 카드 모양, 다른 섹션, 다른 문구** — 형태로 구분하지 않는다(우열이 아니라 종류가 다르다)
7. 하단 고정 — `button-primary` [저장하기] → 저장 후 [저장됨 · 나만의 지도에서 보기]

```
+--------------------------------------------------+
| [← 뒤로]                                         |
| [       사진 16:9                          ]     |
| [place-detail-title  정동진 모래시계공원]        |
| [place-card-meta  강릉시 강동면 · 관광지]        |
| [data-source-note  한국관광공사 KorService2 …]   |
|============ section-gap 48px ==================== |
| [section-heading 언제 갈까요]                    |
| [ 날짜가 정해졌어요 | 한산한 날에 갈래요 ]        |
| [ 30일 예측 — 날짜 그리드 또는 한산 예상일 ]      |
| [data-source-note 이 장소 자체 기준 · 06:00 기준] |
|============ section-gap 48px ==================== |
| [section-heading 지금 가는 길]                   |
| (●) 주변 도로 원활 · 평균 48km/h                 |
| (●) 진입로 서행 · 평균 21km/h                    |
| [no-data-badge 현재 주차 정보 없음]              |
| [data-source-note 국가교통정보센터 · 14:20 조회  |

| [section-heading 대신 가볼 만한 곳]              |
| [place-card][place-card][place-card] →  가로스크롤|
|============ section-gap 48px ==================== |
| [section-heading 함께 가기 좋은 곳]              |
| [place-card][place-card] →                       |
|--------------------------------------------------|
| [button-primary          저장하기            ]   |  ← 하단 고정
```

**반응형.** 최대 1024px 중앙 1단. 데스크톱에서 5·6번 가로 스크롤은 3열 그리드로 펼친다. 하단 고정 버튼은 데스크톱에서 우측 상단으로 이동한다.

**상태 화면.**

| 상태 | 배치 |
|---|---|
| loading | 사진·섹션별 스켈레톤. 섹션 뼈대는 먼저 보인다 |
| **부분 결측 (가장 흔한 상태)** | 섹션은 **남고** 안에 `no-data-badge`. **섹션을 숨기지 않는다** — 빈자리는 좋은 소식으로 읽힌다 |
| error (섹션 단위) | 그 섹션만 `error-state` + [다시 시도]. **다른 섹션은 그대로 산다** |
| 없는 장소 | `error-state` + `button-primary` [탐색 홈으로] |
| 긴 한국어 | 제목 말줄임 없음(다 보여준다) · 대체지 카드 제목 2줄 |
| 대체지/함께 0건 | 섹션 유지 + `empty-state` "지금은 확인된 후보가 없어요". **빈 추천을 감추지 않는다** |

### 나만의 지도 `/saved`

**목적 / 핵심 과업.** 저장한 장소를 지도에서 다시 훑고, 태그·메모·방문 예정일을 손본다.

**존 구조.** 탐색 홈과 같은 지도+시트 골격을 **의도적으로 재사용**한다(일관성 · 학습 비용 0). 다른 점 셋:

1. **지도에 방문 규모 색이 없다** — 마커만. 개인 화면이 인기 순위를 나타내지 않는다(ADR-0005).
2. 시트 헤더가 `section-heading` "저장한 곳 7곳" + **`tag-chip` 필터 열**(정렬 토글 없음).
3. 카드는 `save-button-saved` 상태 고정이고, 탭하면 저장 편집 시트가 열린다.

**상태 화면.**

| 상태 | 배치 |
|---|---|
| empty | **빈 지도를 보여주지 않는다.** 화면 전체가 `empty-state` + `page-title` "아직 저장한 곳이 없어요" + `button-primary` [탐색 홈에서 둘러보기] (ADR-0005 명시) |
| 손상된 로컬 데이터 | 정상 항목은 그대로 표시하고, 목록 상단에 `error-state` 한 줄 "일부 저장 정보를 읽지 못했어요". **화면 전체를 중단시키지 않는다** (슬라이스 #9 AC) |
| 저장 장소의 원본이 사라짐 | 카드는 남기고 `no-data-badge` "최신 정보를 불러오지 못했어요" |

### 시트 3종 (검색 · 날짜 · 저장 편집)

셋 다 같은 규칙을 따른다:

- **히스토리 엔트리를 가진다** → 브라우저 뒤로가기가 한 겹씩 닫는다 (H3 비상구).
- 시트 상단에 `[✕ 닫기]` 상시 노출. 배경 탭으로도 닫힌다.
- 시트 안에서 파괴적 동작(저장 삭제)은 **한 단계 확인**을 거친다 (H5 에러 예방).

| 시트 | 존 구조 | 상태 |
|---|---|---|
| **검색** | `search-field` + `search-field-placeholder` / `theme-chip`·`theme-chip-selected` 8개 / 결과 목록 | 정규화 알림("'벚꽃축제'를 지원 테마 '벚꽃'으로 찾았어요") · 일반 검색이면 `general-search-notice` **상단 고정** · 0건이면 `empty-state` + 가까운 지원 테마 제안 |
| **날짜** | 모드 탭 2개 / 30일 캘린더 / `button-primary` [적용] | **30일 밖 날짜는 `button-primary-disabled`** — 사후 에러 메시지가 아니라 구조로 예방(H5). 예측 결측일은 `no-data-badge` |
| **저장 편집** | `tag-chip` 추가/제거 / `memo-field` / 방문 예정일 / `divider` / `button-secondary` [저장 취소] | 메모는 편집 중 최대 높이 후 내부 스크롤, 보기에서 6줄 후 접기 · 저장 삭제는 확인 1단계 |

## Navigation & IA

**전역 크롬은 하단 내비 하나뿐이다** — `탐색 홈` · `나만의 지도(저장 개수 배지)`. 두 페이지가 IA의 최상위이고, 나머지는 전부 그 아래다.

```
탐색 홈 /  ─┬─ (시트) 검색 ?q=
            ├─ (시트) 날짜 ?date=
            ├─ (오버레이) 첫 사용 안내   ⚠동작경계
            └─ 관광지 상세 /places/:id ─── (시트) 저장 편집 /places/:id/save
나만의 지도 /saved ─┬─ 관광지 상세 /places/:id
                    └─ (시트) 저장 편집
오류 *  →  탐색 홈
```

- **모든 화면에서 하단 내비가 살아 있다** — 상세와 시트 포함. 어디서든 두 최상위로 한 번에 돌아간다.
- **탐색 상태(지도 중심·줌·필터·정렬·시트 스냅)는 URL 쿼리로 유지한다.** 상세에서 뒤로 왔을 때 탐색이 초기화되면 F1·F2·F3가 통째로 무너진다. 새 데이터도 새 엔드포인트도 필요 없고, 이미 결정된 "지도 경계로 목록 조회" 계약을 그대로 쓴다 → **구조**.
- **저장 개수 배지가 두 화면을 잇는 상시 연결**이다(ADR-0005의 "컬렉션이 보조 기능으로 묻히는 위험 완화").

## Do's & Don'ts (structural)

- **Do 데이터·동작이 필요한 걸 조용히 그리지 마라.** 그려도 되지만 `⚠동작경계`를 **세 곳**(페이지 인벤토리 · UX 감사 분류 칸 · 여기)에 같이 붙인다. 표시 없는 화면은 3단계에서 데이터 없는 구멍이 된다.
- **Do 모든 동적 영역에 네 상태**(정상 · 빈 · 에러 · 정보 없음)를 **독립적으로** 준다. 이 제품에서 부분 결측은 예외가 아니라 가장 흔한 상태다.
- **Don't 한 섹션의 실패로 화면 전체를 덮지 마라.** 상세의 다섯 섹션은 서로의 생존에 의존하지 않는다.
- **Don't 빈 상태를 막다른 길로 두지 마라.** 모든 `empty-state`는 다음 행동 버튼을 가진다.
- **Do 지도 색(지역 방문 규모)과 목록 정렬(온라인 언급량)을 시각적으로 다른 블록에 둬라.** 시트 경계가 그 분리선이다 (ADR-0002 · 0006).
- **Don't 결측을 정렬에 섞지 마라.** 온라인 언급 정보가 없는 장소는 정렬 구간 밖 별도 구간이다.
- **Do 모든 시트에 히스토리 엔트리와 `[✕]`를 줘라** (H3 비상구).
- **Do 불가능한 선택을 애초에 비활성으로 막아라** — 30일 밖 날짜 (H5 에러 예방).
- **Do 탐색 상태를 URL에 남겨라.** 뒤로가기가 탐색을 초기화하면 핵심 흐름 셋이 무너진다.
- **Don't 여기서 비주얼을 결정하지 마라** — 색·서체·그림자는 DESIGN.md의 것이고 3단계에서 적용된다. 이 문서의 미리보기는 흑백이다.
- **Don't 여기서 동작을 바꾸지 마라** — 데이터 흐름·API 계약·서버액션·핵심 스키마·비즈니스 로직 불가침.
