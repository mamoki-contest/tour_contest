## Overview

**한사나다는 강원도 18개 시·군의 관광지를 지도로 발견하고, 각 장소의 향후 30일 중 상대적으로 한산한 날을 골라, 로그인 없이 개인 컬렉션에 모아두는 모바일 우선 반응형 웹이다.**

**핵심 사용자.** 강원도로 떠나기 전 휴대폰으로 후보를 추리는 사람. 계정이 없고, 만들 생각도 없다. `온라인 언급량`·`기준 시점` 같은 말을 모르고 알 필요도 없다.

**상위 과업 (JTBD).**
> "강원도에 가고 싶다. 유명한 데는 붐빌 것 같고, 안 붐비는 데는 어딘지 모르겠다. **갈 만한 장소 몇 곳과 언제 갈지를 정해서, 잊어버리기 전에 모아두고 싶다.**"

이 과업이 구조를 지배하는 방식은 하나다 — **화면은 장소를 평가해 주지 않고, 사용자가 스스로 좁혀 나가게 한다.** DESIGN.md의 시금석("굵은 글씨가 장소를 평가하나, 데이터를 진술하나")이 배치에서는 이렇게 번역된다: 어떤 화면도 "여기로 가세요"라는 단일 결론을 내지 않고, **범위를 좁히는 도구와 그 근거를 같이 놓는다.**

**이번 패스 미사용 컴포넌트: `region-search-button` 하나.** 지도 이동이 자동으로 목록을 갱신하게 되면서 누를 것이 없어졌다(#48). DESIGN.md 에는 정의가 남아 있으므로 51개 중 50개가 배치됐다(§커버리지 참조).

## User Flows

동적 화면이라 wireflow(와이어프레임 + 흐름 화살표)로 문서화한다. 화살표 뒤 괄호는 그 스텝에서 바뀌는 상태다.

**F1 — 무테마 발견** (사용자 스토리 1·2)
```
탐색 홈 진입
  → [지도] 18개 시·군 방문 규모 색 비교 (시트: 중간 스냅, 카드 2~3장 보임)
  → 시·군 탭, 또는 지도를 움직이면 **누르지 않아도** 보이는 범위로 목록 갱신 (조작이 멎고 400ms · bbox 확정 · 시·군 조건 해제)
  → [시트 헤더] 온라인 언급 많은 순 ⇄ 온라인 언급 적은 순 전환 (정렬 반전 · 정보 없음 구간은 하단 고정)
  → [시트 헤더 ⓘ] 도움말 시트 (?sheet=help) — 신호가 무엇을 센 값인지 여기서 한 번 (뒤로가기로 닫힘)
  → [더 보기] 20곳씩 누적 (주소의 page · 100곳에서 끝 안내)
  → 카드 탭 → 관광지 상세
```

**F2 — 테마 · 검색으로 좁히기** (사용자 스토리 3)
```
탐색 홈 → 조건 요약 줄의 테마·검색 칩(`무테마` / 테마명 / `'검색어' 검색`) 탭 → 검색 시트
  ├ 지원 테마 칩 선택 (벚꽃 등 8개)      → 결과: 지원 테마 (추천 자격·큐레이션 통과)
  └ 자유 입력 → 지원 테마로 정규화되면 그 사실을 문장으로 알림
                 정규화 실패 → 결과: 일반 검색 ([general-search-notice] 상단 고정)
  → 카드 탭 → 관광지 상세
```

**F3 — 날짜로 좁히기** (사용자 스토리 4·5)
```
첫 진입 / — 날짜 미정: 카드에 예측 배지가 없다 (#53)
  → [조건 요약 줄의 `날짜 미정`] 탭 → 날짜 시트
  ├ `날짜가 정해졌어요` → 예측 창 캘린더에서 하루 선택 (창 밖은 비활성 · 창은 응답이 말한다)
  │     → 칩 `9월 24일` · 카드에 [crowd-badge] `이 장소 기준 한산/보통/혼잡`
  ├ `한산한 날에 갈래요`
  │     → 칩 `한산한 날` · 카드에 [quiet-date-value] 장소별 한산 예상일
  └ `날짜 조건 없이 볼래요` → 칩 `날짜 미정` 으로 되돌아간다 (예측을 다시 묻지 않는다)
  → 카드 탭 → 상세에서 예측 창 전체 확인 (상세의 30일 예측·한산 예상일은 날짜 상태와 무관하다)
```

> **예측은 물어본 사람에게만 보인다 (#53 · 사용자 결정 2026-09-21).** 날짜 상태는 셋이고(`날짜 미정` · `한산한 날` · `9월 24일`), 첫 진입은 **미정**이다. 미정에서는 목록 조회에 `dateMode` 를 **보내지 않아** 백엔드가 예측을 계산하지 않는다 — 카드가 그리지도 않을 값이고, 첫 진입은 가장 잦은 조회다. 상세는 반대다: 이미 한 장소를 열어 `언제 갈까`를 읽는 자리라 30일 예측과 한산 예상일이 날짜 상태와 무관하게 그대로 선다.

**F4 — 검토 → 저장 → 다시 보기** (사용자 스토리 6·7)
```
관광지 상세
  → 기본정보 → 언제 갈까요(30일 예측) → 지금 가는 길(도로·주차) → 대신 가볼 만한 곳 → 함께 가기 좋은 곳
  → [button-primary 저장하기] → 저장 편집 시트 (태그·메모·방문 예정일)
  → 저장 완료 → 같은 자리 버튼이 [저장됨 · 나만의 지도에서 보기]로 전환 (별도 토스트 없음)
  → 나만의 지도 → 저장 장소만 지도+목록 → 카드 탭 → 상세(최신 정보 재조회)
```

> **R1 확정 (2026-09-21) — 첫 사용 안내를 시트 자동 노출로 만들지 않는다.** PRD #10은 *"지도 색상과 관심도는 실제 인파가 아니라는 안내를 첫 사용 및 범례에서 제공한다"*고 요구하고, 이 문서는 **"이미 봤음" 플래그를 어디에 두는지**를 미결로 남겨 개발 체인에 넘겼었다. 개발 체인의 답은 아래 「Open Decisions · R2」에 적었다 — **localStorage 키 하나**(`hansanada.help.seen`)이고 개인 컬렉션 스키마에 넣지 않으며, 첫 방문에 시트를 자동으로 띄우지 않고 **ⓘ 옆 점 하나**로만 알린다. 그래서 인벤토리에서 `첫 사용 안내 시트` 행이 사라지고 `도움말 시트` 행이 그 자리를 받았다.

## Per-Page Layout

### 탐색 홈 `/`

**목적 / 핵심 과업.** 지도로 지역을 비교해 범위를 정하고, 그 범위 안 관광지를 훑어 상세로 들어갈 후보를 고른다.

**존 구조 (모바일 · 우선순위 순)**

1. **지도 (전면)** — 화면 전체. `map-region-fill-1..4` 면, `map-region-outline` 경계, `map-region-fill-nodata` 사선 해칭, `map-place-label` 흰 알약 마커 라벨.
2. **상단 컴팩트 바 (지도 위 플로팅)** — **조건 요약 줄**만. 검색 입력(`search-field`)은 상단 바에 두지 않고 **검색 시트 안에만** 둔다(#44 확정 — 시트 방식 유지, 지도 면적 보존). 조건 요약은 가로 스크롤 칩 열이다: `강원 전체` `무테마` `날짜 미정` `온라인 언급 많은 순` — 각각 탭하면 해당 시트가 열리고, 끝에 `[초기화]`. **날짜 칩은 세 문구를 갈라 말한다**(#53): `날짜 미정`(첫 진입) · `한산한 날`(한산한 날에 갈래요) · `9월 24일`(고른 날짜). 셋이 갈라지기 전에는 `한산한 날에 갈래요` 를 고른 화면도 `날짜 미정` 이라고 말했다 — 칩이 사용자의 선택을 부정하는 동안 카드에는 그 예측이 떠 있었다.
3. **지도 위 액션** — 없다. 지도를 움직이면 **자동으로** 보이는 범위를 다시 조회하므로 누를 것이 없다(#48). 바뀌었다는 사실은 시트 헤더의 `N곳` 과 조건 칩 `이 지도 범위` 가 말한다.
4. **범례** — `map-legend`. 색 구간 · 사선(정보 없음) · **기준 기간 한 줄**. 공급자 이름은 싣지 않는다. **접히지 않는다.** 자리는 폭에 따라 둘이다 — **모바일은 시트 바로 위에 붙어 따라 올라가고**(시트에 가리지 않는다 · U1), **데스크톱(1024px~)은 지도 좌하단에 고정**된다(시트가 없어졌으므로 따라갈 것이 없다). 지도가 실패해도 그린다 — 방문 규모 값과 기준 기간은 지도와 함께 죽지 않고, 색을 못 칠하는 동안 이 카드가 시·군 시트로 가는 입구가 된다.
5. **목록 바텀시트** — 세 스냅: `접힘(peek)` 헤더만 / **`중간` 화면의 55% = 첫 진입 기본** / `펼침` 상단 여백만 남김.
   - 시트 헤더: 핸들 · `section-heading`(아래 「시트 헤더 문구」) · `sort-toggle-item` / `-selected`(`온라인 언급 많은 순` / `온라인 언급 적은 순`) · **`help-button` ⓘ**
   - 헤더 하단 고정 `data-source-note`: **기준 시점 한 줄**. 공급자 이름도 해명 문장도 싣지 않는다 — 정렬 라벨이 이미 무엇을 센 값인지 말한다. 값이 `STALE` 이면 그 줄이 `최근 저장된 정보 · 3시간 전 기준`으로 바뀐다(낡았다는 사실이 시점보다 먼저 온다). 정렬이 적용되지 않았으면 그 사실을 먼저 한 줄로 밝힌다("지금은 온라인 언급 정보가 없어 순서를 매기지 않았어요")
   - 쓸 수 없어 버린 조건이 있으면 그 아래 한 줄 — `고른 날짜는 예측이 닿지 않아 날짜 조건을 풀었어요` · `그 시·군을 찾을 수 없어 강원 전체로 보여드려요`. **어긋난 조건 하나 때문에 목록 전체를 잃지 않되, 무엇이 빠졌는지는 반드시 말한다.**
   - 본문: `place-card` 반복 → (`divider`) → **`순서를 매기지 못한 N곳` 구간** → **`더 보기`**
6. **하단 내비** — `bottom-nav-item` / `-active` + `saved-count-badge`. **시트 위에 항상 뜬다**, 시트 콘텐츠 하단에 내비 높이만큼 여백.

**시트 헤더 문구 (#25).** 헤더는 **지금 걸린 조회 범위**를 말한다. **무엇을 찾았는지(테마·검색어)가 주어**이고, **어디에서 찾았는지는 기본값이 아닐 때만** 앞에 붙는다 — `강원 전체 해수욕장`은 아무것도 좁히지 않은 말이다.

| 조건 | 헤더 |
|---|---|
| (없음) | `강원 전체 4,741곳` |
| 춘천시 | `춘천시 412곳` |
| 해수욕장 테마 | `해수욕장 113곳` |
| `?q=커피` | `'커피' 검색 53곳` |
| 지도 경계 확정 | `이 지도 범위 N곳` |
| 강릉시 + 해수욕장 | `강릉시 해수욕장 12곳` |

개수를 모르면 범위만 말한다(`춘천시`). 지도 경계가 확정돼 있을 때만 `이 지도 범위`라고 말할 수 있다 — 사용자가 아직 지도를 움직이지 않았으면(첫 진입) 조회 범위가 바뀐 것이 아니다.

**`더 보기` (#30 M4).** 쪽을 나눠 따로 보여주지 않고 **읽던 목록을 늘린다** — 20곳씩, 주소의 `page` 가 늘면 한 번에 더 크게 부른다(`size = 20 × page`). 쪽 수가 주소에 적히므로 상세에 들어갔다 돌아와도 늘려 둔 자리가 그대로 있다(U6).

- **`더 보기` 자리는 스켈레톤으로 덮지 않는다.** 읽던 줄을 잃기 때문이다 — 버튼 자신이 진행 중임을 말한다(`불러오는 중`). 스켈레톤은 조회 조건이 실제로 바뀐 이동에서만 켜진다(시·군·테마·검색어·날짜·정렬). **지도 이동은 예외다**(#48): 조회 조건(`bbox`)이 분명히 바뀌는데도 이전 목록을 그대로 두고, 헤더의 `N곳` 이 갱신되는 것으로 바뀌었음을 말한다 — 지도를 훑는 동안 목록이 회색 카드로 바뀌었다 돌아오기를 되풀이하면 방금 본 곳이 어디였는지 잃는다. 시트를 열고 닫는 것으로도 읽던 목록이 사라지면 안 된다.
- **100곳에서 끝난다.** 백엔드 한 번 조회의 최대 개수다. **끝에 닿았다는 사실을 숨기고 버튼만 지우지 않는다** — 그러면 목록이 여기까지인 줄 안다. 대신 다음 행동을 준다: `여기까지 N곳을 봤어요. 시·군이나 테마로 좁히면 나머지를 찾을 수 있어요.`

**`순서를 매기지 못한 N곳` divider (#27 · U17 · D7).** **뒤가 전부 미산정일 때만** 선을 긋는다. 중간에 섞여 있다면 그것은 우리가 아는 경계가 아니라 받은 순서일 뿐이고, 거기에 선을 그으면 없는 구조를 지어내는 셈이 된다.

- **0건은 미산정이 아니다.** 정상 수집으로 0건을 센 것은 정상 값이고, 그것까지 구역 아래로 내리면 확인된 사실을 확인하지 못한 것으로 바꾸게 된다.
- **검색 결과에는 그리지 않는다.** 검색 입구는 정렬을 받지 않아 미산정이 뒤쪽에 모여 온다는 보장이 없다.
- 왜 순서를 매기지 못했는지는 **도움말**이 말한다 — divider 자체는 한 줄이다.
- **문구는 #49에서 바뀌었다.** 전에는 `온라인 언급 정보 없음 N곳`이었는데, 카드에서 언급량을 걷어낸 뒤로는 화면 어디에도 없는 숫자를 divider 가 혼자 아쉬워하는 꼴이 됐다. 지금 문구는 사용자가 보고 있는 것(순서)으로 말하고, 정렬이 적용되지 않았을 때 헤더가 쓰는 말(`순서를 매기지 않았어요`)과 어휘를 맞췄다. **`순위 밖`이라고 줄이지 않는다** — 그것이 정확히 #27이 막으려는 오해다.

### 관광지 상세 `/places/:id`

**목적 / 핵심 과업.** 다섯 종류의 정보를 **섞이지 않게** 확인하고 저장할지 정한다.

**존 구조 (위→아래 · 섹션 사이 `section-gap` 48px)**

1. 상단 고정 바 — `[← 뒤로]`(H3 비상구). 스크롤하면 관광지 이름이 축약돼 따라온다. **href 는 언제나 앱 안의 실제 주소**(걸려 있던 탐색 조건을 그대로 들고 가는 `/?…`)이고, 히스토리 뒤로가기는 **앱 안에서 들어왔을 때만** 클릭에서 쓴다 — 링크로 곧장 들어온 첫 진입에서 뒤로가기를 부르면 비상구가 사이트 밖으로 나가는 출구가 된다. 그리고 href 가 없으면 가운데 클릭·새 탭·링크 복사가 전부 제자리를 가리킨다.
2. 사진 (16:9) → `place-detail-title` (말줄임 없음) → `place-card-meta` 주소·분류 → `data-source-note` **기준 시점 한 줄** + `ⓘ 이 화면의 정보들`
3. **언제 갈까요** — `section-heading` / 날짜 모드 탭 / 예측 창 그리드 / `crowd-badge-*` 또는 `quiet-date-value` / `data-source-note` **기준 시점 한 줄**. "이 장소 자체 기준"이라는 해명은 캡션에서 빼고 **도움말**로 옮겼다 — 배지 문구가 이미 `이 장소 기준 한산`이라고 말한다 (#35)
4. **지금 가는 길** — `section-heading` / `road-status-dot-smooth|slow|jam` + `place-detail-body` 라벨 / **주차 네 상태**(아래) / `data-source-note` **조회 시각 한 줄**. 도로와 주차는 공급자도 시각도 달라 **각자의 상태와 각자의 캡션**을 가진다(U7). "미래 날짜 인파와 다른 정보"라는 해명도 도움말로 옮겼다 — 섹션 제목 `지금 가는 길`과 `48px` 간격이 그 일을 한다 (U20 · #35)

**주차 네 상태 (상세 「지금 가는 길」).**

| 상태 | 화면 |
|---|---|
| 실시간을 아는 주차장 | `이름 · 거리 · 잔여 N면 / 총 M면` + 등급 배지(`여유`·`보통`·`혼잡`·`만차`). 잔여면이 등급보다 앞에 온다 |
| 규모만 아는 주차장 | `실시간 잔여 정보 없음 · 주차장 규모만 확인했어요`(실시간 줄이 있으면 `그 밖의 주차장은 규모만 알아요 · 실시간 잔여 정보 없음`) + `이름 · 거리 · 총 N면`. 앞의 세 곳까지만 적고 나머지는 `그 밖에 반경 1km 안에 N곳이 더 있어요`로 센다 |
| 반경 안에 없다 | 채운 글자로 `반경 1km 안에 주차장이 없어요` — **배지가 아니다.** 확인이 끝난 사실이다 |
| 확인하지 못했다 | `no-data-badge` `주차 정보를 확인하지 못했어요` |

**`확인했고 없다`와 `확인하지 못했다`를 같은 말로 덮지 않는다.** 앞엣것은 확인이 끝난 사실이고 뒤엣것은 아직 모른다는 고백이라, 형태부터 다르다. 실시간 값이 하나도 없으면 **조회 시각 캡션 자체를 그리지 않는다** — 반기마다 갱신되는 정적 정보에 시각을 달면 방금 본 값처럼 읽힌다.
5. **대신 가볼 만한 곳** — `place-card` 가로 스크롤. 추천 자격을 통과한 **관광지만**
6. **함께 가기 좋은 곳** — `place-card` 가로 스크롤. 음식점·숙박. **같은 카드 모양, 다른 섹션, 다른 문구** — 형태로 구분하지 않는다(우열이 아니라 종류가 다르다)
7. 하단 고정 — `button-primary` [저장하기] → 저장 후 [저장됨 · 나만의 지도에서 보기]

| **부분 결측 (가장 흔한 상태)** | 섹션은 **남고** 안에 `no-data-badge`. **섹션을 숨기지 않는다** — 빈자리는 좋은 소식으로 읽힌다 |
| error (섹션 단위) | 그 섹션만 `error-state` + [다시 시도]. **다른 섹션은 그대로 산다** |
| 없는 장소 | `error-state` + `button-primary` [탐색 홈으로] |
| 긴 한국어 | 제목 말줄임 없음(다 보여준다) · 대체지 카드 제목 2줄 |
| 대체지/함께 0건 | 섹션 유지 + `empty-state` "지금은 확인된 후보가 없어요". **빈 추천을 감추지 않는다** |

### 나만의 지도 `/saved`

**목적 / 핵심 과업.** 저장한 장소를 지도에서 다시 훑고, 태그·메모·방문 예정일을 손본다.

**존 구조.** 탐색 홈과 같은 지도+시트 골격을 **의도적으로 재사용**한다(일관성 · 학습 비용 0). 다른 점 셋:

1. **지도에 방문 규모 색이 없다** — 마커만. 개인 화면이 인기 순위를 나타내지 않는다(ADR-0005).
2. 시트 헤더가 `section-heading` "저장한 곳 7곳" + **`tag-chip` 필터 열**(정렬 토글 없음).
3. 카드는 `save-button-saved` 상태 고정이고, 탭하면 저장 편집 시트가 열린다.

**상태 화면.**

| 상태 | 배치 |
|---|---|
| empty | **빈 지도를 보여주지 않는다.** 화면 전체가 `empty-state` + `page-title` "아직 저장한 곳이 없어요" + `button-primary` [탐색 홈에서 둘러보기] (ADR-0005 명시) |
| **일부** 손상 | 정상 항목은 그대로 표시하고, 목록 상단에 `error-state` 한 줄 "일부 저장 정보를 읽지 못했어요". **화면 전체를 중단시키지 않는다** (슬라이스 #9 AC) |
| **통째** 손상 (#28) | **빈 상태 문구를 띄우지 않는다** — `아직 저장한 곳이 없어요`와 나란히 뜨면 어느 쪽이 사실인지 알 수 없고, 되돌릴 버튼이 없으면 영영 그 화면이다. 대신 `error-state`: `저장 정보를 읽을 수 없어요` + `지우면 저장해 둔 곳과 태그·메모가 함께 사라지고 되돌릴 수 없어요.` + [지우고 새로 시작하기] → **한 단계 확인**([그대로 두기] / [지우고 새로 시작], H5). 확인 전까지 원본은 그대로 남는다 |
| 저장 장소의 원본이 사라짐 | 카드는 남기고 `no-data-badge`. **사라진 것과 못 본 것을 가른다** — `더 이상 찾을 수 없는 곳이에요 — 정리해도 괜찮아요` / `이번에는 확인하지 못했어요 — 사라진 곳은 아니에요` |

화면 맨 아래에 `ⓘ 이 화면의 정보들` — 저장이 이 브라우저에만 남는다는 설명도 **도움말 한 자리**에 있다(#35).

- **히스토리 엔트리를 가진다** → 브라우저 뒤로가기가 한 겹씩 닫는다 (H3 비상구).

## Navigation & IA

**전역 크롬은 하단 내비 하나뿐이다** — `탐색 홈` · `나만의 지도(저장 개수 배지)`. 두 페이지가 IA의 최상위이고, 나머지는 전부 그 아래다.

```
탐색 홈 /  ─┬─ (시트) 검색   ?sheet=search
            ├─ (시트) 날짜   ?sheet=date
            ├─ (시트) 시·군  ?sheet=region
            ├─ (시트) 도움말 ?sheet=help   ← 상세·저장 화면에서도 같은 시트
            └─ 관광지 상세 /places/:id ─── (시트) 저장 편집 /places/:id/save
나만의 지도 /saved ─┬─ 관광지 상세 /places/:id
                    └─ (시트) 저장 편집
오류 *  →  탐색 홈
```

- **모든 화면에서 하단 내비가 살아 있다** — 상세와 시트 포함. 어디서든 두 최상위로 한 번에 돌아간다.
- **탐색 상태(지도 중심·줌·필터·정렬·시트 스냅)는 URL 쿼리로 유지한다.** 상세에서 뒤로 왔을 때 탐색이 초기화되면 F1·F2·F3가 통째로 무너진다. 새 데이터도 새 엔드포인트도 필요 없고, 이미 결정된 "지도 경계로 목록 조회" 계약을 그대로 쓴다 → **구조**.

### 지도와 URL 상태

| 값 | 뜻 | 조회 조건인가 |
|---|---|---|
| `region` | 선택된 시·군 | ○ |
| `bbox` | 지도가 멎은 뒤 자동으로 확정되는 보이는 범위 (`swLat,swLng,neLat,neLng`) | ○ |
| `c` · `z` | 지도가 보고 있는 **자리** — 중심(`lat,lng`)과 확대 단계 | ✕ |
| `theme` · `q` · `dateMode` · `date` · `sort` · `page` | 목록 조회 조건 | ○ |
| `snap` · `sheet` | 시트 스냅 · 열려 있는 시트 | ✕ |

- **`region` 과 `bbox` 는 서로를 지운다.** 둘을 같이 두면 조회 범위가 어느 쪽도 아니게 되는데, 조건 칩은 시·군 이름만 말해 사용자가 그 사실을 알 수 없다. 지도 범위를 확정하면 시·군이 풀리고, 시·군을 고르면 경계가 풀린다 — 어느 쪽이든 쪽 수(`page`)도 첫 쪽으로 되돌린다. 늘려 둔 쪽은 **다른 목록의 쪽**이기 때문이다.
- **`c`·`z` 는 조회 조건이 아닌데도 주소에 싣는다.** 상세로 들어갔다 뒤로 오면 지도가 다시 마운트되므로, 자리가 주소에 없으면 축척이 강원 전체로 되돌아간다(U6). `bbox` 만으로는 모자라다 — 첫 진입이나 시·군으로 옮겨 간 직후에는 `bbox` 자체가 없다. 그래서 **`초기화` 칩은 `c`·`z` 를 세지 않는다**: 지도를 민 것만으로 나타나면 지울 조건이 없는데도 지우라고 권하는 셈이다. 적히는 때도 다르다 — `c`·`z` 는 손을 떼는 **즉시**(조회를 돌리지 않으므로 싸다), `bbox` 는 조작이 **멎은 뒤 한 번**.
- **기본값과 같은 항목은 주소에 쓰지 않는다** — 주소가 실제로 걸린 조건만 말하게 한다.
- **`dateMode` 는 세 값이고 기본은 `NONE`(날짜 미정)이다** (#53). `NONE` 이면 주소에서 생략하고, `FLEXIBLE` 은 **주소에 남기며**(기본값이 아니므로), `FIXED` 는 `date` 와 함께 적는다. `dateMode` 가 없는 옛 주소는 `NONE` 으로 읽는다 — 그 링크들이 가리키던 화면도 `날짜 미정` 이었고, 없음을 `FLEXIBLE` 로 읽으면 묻지도 않은 예측을 들고 열린다. 예측이 닿지 않는 날짜를 버릴 때도 되돌아가는 자리는 `NONE` 이다(#13의 날짜 조건 해제) — 고르지도 않은 `한산한 날` 로 떨어뜨리는 것 역시 사용자의 선택이 아니다.
- **받는 입은 넓게, 내는 입은 좁게.** 폐기된 옛 정렬 값(`INTEREST_*`)도 읽어 주되 새로 만드는 주소에는 현행 값(`MENTION_*`)만 쓴다. 옛 링크는 이미 공유되고 북마크됐고, 받아 주지 않으면 사용자는 자기가 고른 방향이 뒤집힌 줄도 모른다.
- **주소를 손댄 값은 뜻을 지어내지 않고 되돌린다.** 깨진 경계·범위 밖 확대 단계·모르는 정렬 값은 버린다. **다만 버렸다는 사실은 말한다** — 예측이 닿지 않는 날짜나 없는 시·군은 그 조건만 풀고 목록은 살리되, 무엇이 빠졌는지 한 줄로 알린다(위 「탐색 홈 · 상태 화면」).
- **저장 개수 배지가 두 화면을 잇는 상시 연결**이다(ADR-0005의 "컬렉션이 보조 기능으로 묻히는 위험 완화").

## Do's & Don'ts (structural)

- **Do 데이터·동작이 필요한 걸 조용히 그리지 마라.** 그려도 되지만 `⚠동작경계`를 **세 곳**(페이지 인벤토리 · UX 감사 분류 칸 · 여기)에 같이 붙인다. 표시 없는 화면은 3단계에서 데이터 없는 구멍이 된다.
- **Do 모든 동적 영역에 네 상태**(정상 · 빈 · 에러 · 정보 없음)를 **독립적으로** 준다. 이 제품에서 부분 결측은 예외가 아니라 가장 흔한 상태다.
- **Don't 한 섹션의 실패로 화면 전체를 덮지 마라.** 상세의 다섯 섹션은 서로의 생존에 의존하지 않는다.
- **Don't 빈 상태를 막다른 길로 두지 마라.** 모든 `empty-state`는 다음 행동 버튼을 가진다.
- **Do 지도 색(지역 방문 규모)과 목록 정렬(온라인 언급량)을 시각적으로 다른 블록에 둬라.** 시트 경계가 그 분리선이다 (ADR-0002 · 0006).
- **Don't 결측을 정렬에 섞지 마라.** 온라인 언급 정보가 없는 장소는 정렬 구간 밖 별도 구간이다. 다만 **뒤가 전부 미산정일 때만** 선을 긋는다 — 없는 경계를 지어내지 않는다.
- **Do 신호 설명은 도움말 한 곳에 모아라.** 화면 캡션은 **기준 시점 한 줄**이다. 같은 해명을 화면마다 반복하면 정작 사용자가 행동하는 데 필요한 것을 덜 말하게 된다.
- **Don't 조건 하나가 어긋났다고 화면을 통째로 잃게 하지 마라.** 그 조건만 풀고 목록은 살리되, **무엇이 빠졌는지는 반드시 한 줄로 말한다.**
- **Do 읽던 목록을 덮지 마라.** 스켈레톤은 조회 조건이 실제로 바뀐 이동에서만 켠다. `더 보기`와 시트 여닫기는 읽던 줄을 지우지 않는다.
- **Do 끝에 닿았으면 끝났다고 말해라.** 버튼만 조용히 지우면 사용자는 목록이 거기까지인 줄 안다.
- **Do 모든 시트에 히스토리 엔트리와 `[✕]`를 줘라** (H3 비상구).
- **Do 불가능한 선택을 애초에 비활성으로 막아라** — 30일 밖 날짜 (H5 에러 예방).
- **Do 탐색 상태를 URL에 남겨라.** 뒤로가기가 탐색을 초기화하면 핵심 흐름 셋이 무너진다.
- **Don't 여기서 비주얼을 결정하지 마라** — 색·서체·그림자는 DESIGN.md의 것이고 3단계에서 적용된다. 이 문서의 미리보기는 흑백이다.
- **Don't 여기서 동작을 바꾸지 마라** — 데이터 흐름·API 계약·서버액션·핵심 스키마·비즈니스 로직 불가침.

**흐름의 집.** F1→탐색 홈 · F2→탐색 홈+검색 시트 · F3→날짜 시트+카드+상세 · F4→상세+저장 편집 시트+나만의 지도. PRD #10의 사용자 스토리 7개가 전부 집을 가진다.
