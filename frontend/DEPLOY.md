# 프론트엔드 배포 인수인계

이 문서 하나만 보고 **사용자 로컬과 똑같이 동작하는 상태**로 서버에 올릴 수 있게 쓴 글입니다.
코드는 바꾸지 않습니다 — 지금 `main` 에 있는 그대로 배포됩니다.

| 항목 | 값 |
| --- | --- |
| 배포 대상 | 이 저장소의 **`frontend/`** 디렉터리 (저장소 루트가 아닙니다) |
| 프레임워크 | React Router **8** framework mode, **SSR** (`react-router.config.ts` 의 `ssr: true`) |
| 빌드 | `npm run build` → `react-router build` → `build/client` · `build/server` |
| 직접 띄울 때 | `npm start` → `react-router-serve ./build/server/index.js` (3000 포트) |
| 권장 배포처 | **Vercel** (ADR-0001 이 정한 자리) |
| 백엔드 | `http://211.233.201.61:8080` — 배포·적재 절차는 `tour_backend` 의 `docs/deploy-ncp-docker.md` |

> **먼저 백엔드가 최신인지 확인하세요.** 지금 서버에 떠 있는 백엔드 빌드는 PR #97 이전
> 것이라 사진 보강·검색 상태 노출이 빠져 있습니다. 프론트를 아무리 잘 올려도 카드에 사진이
> 비어 보입니다. `tour_backend` 의 런북 **"재배포 체크리스트"** 절을 먼저 밟으세요.

| --- | --- |

> **값은 안전한 경로로 받으세요 — 이슈·PR·채팅에 붙여 넣지 마세요.** 한 번 올라간 값은

> 넣고(3-2), 로컬에서는 커밋되지 않는 `.env` 에 넣습니다.
>
> **카카오 키는 결국 브라우저에 노출됩니다**(1절). 그렇다고 아무 데나 적어도 되는 것은
> 아닙니다 — 노출되는 자리는 그 키가 등록된 도메인에서 돌아가는 페이지 하나뿐이고,
> 이슈나 채팅에 적으면 그 통제 밖으로 나갑니다.

**백엔드 쪽 키 다섯 개**(`KOR_SERVICE_KEY`, `NAVER_API_HUB_KEY_ID`, `NAVER_API_HUB_KEY`,
`KAKAO_REST_API_KEY`, `ITS_API_KEY`)는 이 앱이 쓰지 않습니다. 브라우저는 물론이고 이 앱의
서버 로더도 외부 관광 API 를 직접 부르지 않습니다 — 언제나 백엔드만 부릅니다(0절).
백엔드 담당이라면 `tour_backend` 의 `docs/deploy-ncp-docker.md` 를 보세요.

**(2) 콘솔 작업 — 하나 남아 있고, 사용자만 할 수 있습니다.**

| 작업 | 상태 |
| --- | --- |
| **카카오 개발자 콘솔에 배포 도메인 등록** | **남아 있습니다.** 배포해서 주소가 나와야 할 수 있는 단계이고(3-4), 콘솔이 **사용자 계정**이라 담당자가 직접 들어갈 수 없습니다. **주소가 정해지면 사용자에게 등록을 요청하세요.** 이걸 빠뜨리면 배포는 성공했는데 지도만 안 뜹니다 |
| 네이버 API HUB 이미지 API 활성화 | **완료** (백엔드 쪽 작업) |
| 공공데이터포털 활용신청 | **완료** (백엔드 쪽 작업) |

**(3) 데이터 파일 — 전달받을 것이 없습니다.**

- 이 앱은 데이터를 보관하지 않습니다. 화면에 뜨는 모든 것은 백엔드에서 옵니다.
- **관광지 사진도 파일이 아니라 주소(URL)입니다.** 백엔드가 `place_image` 표에 URL 만

  붙일 필요도 없습니다. **다만 백엔드에서 `--job=place-image` 를 돌려야 채워집니다** —
  안 돌리면 카드 사진이 통째로 빕니다(4절 3번).

  `tour_backend` 의 `sample/` 에 이미 커밋돼 있습니다. 프론트와는 무관합니다.

**(4) 계정 결정 — 사용자와 먼저 정하세요.**

- **Vercel 계정을 누가 소유할지.** 사용자 계정으로 만들지 담당자 계정으로 만들지에 따라

  인수인계할 때 프로젝트를 옮기거나 사용자를 팀에 초대해야 합니다.
- 이 결정이 **배포 주소**를 정하고, 그 주소가 **카카오 콘솔 도메인 등록**(3-4)과
  **백엔드의 `CORS_ALLOWED_ORIGINS`**(3-5)에 들어갑니다. 그래서 가장 먼저 정합니다.

## 0. 이 앱이 네트워크를 쓰는 방식

뒤에 나오는 결정(CORS 가 왜 필요 없는지, HTTPS-HTTP 가 왜 문제가 아닌지)이 전부 여기서
나오므로 먼저 적습니다. **`frontend/app/` 전체를 훑어 확인한 사실입니다.**

```
[브라우저] ──▶ [Vercel 의 이 앱]  ──▶  [백엔드 211.233.201.61:8080]
     │            서버 로더                    서버-서버 (HTTP)
     │
     ├──▶ dapi.kakao.com          (카카오맵 SDK, HTTPS)
     └──▶ cdn.jsdelivr.net        (Pretendard 폰트, HTTPS)
```

**브라우저는 백엔드를 직접 부르지 않습니다.** 백엔드로 나가는 `fetch` 는 서버 전용 모듈
`app/lib/backend.server.ts` 한 곳뿐이고, 거기서 `process.env.API_BASE_URL` 을 읽습니다.
`app/routes/saved.tsx` 의 `useFetcher` 는 이 앱 자신의 `/saved/lookup` 을 부르는 것이라
같은 출처이고, 백엔드로 가지 않습니다.

이 사실에서 두 가지가 따라 나옵니다.

- **백엔드의 `CORS_ALLOWED_ORIGINS` 는 지금 프론트 동작에 필요하지 않습니다.**
  서버-서버 호출은 CORS 대상이 아닙니다. (그래도 넣어 두라는 이야기는 3-5 에.)
- **Vercel(HTTPS)에서 백엔드(HTTP)를 부르는 것은 mixed content 가 아닙니다.**
  mixed content 는 **브라우저**가 HTTPS 페이지에서 HTTP 를 부를 때 막히는 것인데,
  여기서는 Vercel 의 서버가 부릅니다. 브라우저가 직접 부르는 주소는 위 그림의 카카오·폰트
  뿐이고 둘 다 HTTPS 입니다.

> **나중에 브라우저에서 백엔드를 직접 부르는 코드가 생기면 이 두 가지가 동시에 깨집니다.**
> CORS 가 필요해지고, HTTPS 페이지에서 HTTP 백엔드를 불러 mixed content 로 막힙니다.
> 그때는 백엔드에 TLS 를 붙이거나(도메인+인증서) 이 앱의 서버 라우트를 거치게 해야 합니다.
> 지금 코드는 그 자리에 있지 않습니다.

## 1. 환경 변수 두 개

`frontend/.env.example` 에 설명이 있습니다. **값은 이 문서에 적지 않습니다.**

| 이름 | 누가 읽나 | 없으면 |
| --- | --- | --- |
| `API_BASE_URL` | **서버 로더만.** `process.env` 로 요청 때마다 읽습니다 | 모든 화면이 "정보를 불러오지 못했어요" 로 떨어집니다 |
| `KAKAO_MAP_APP_KEY` | 서버 로더가 읽어 **로더 데이터로 브라우저에 내려보냅니다** | 지도가 뜨지 않고 목록만으로 탐색하는 실패 상태가 됩니다 |

**둘 다 `VITE_` 접두사를 붙이지 마세요.** 이 앱은 두 값을 모두 서버에서 `process.env` 로
읽습니다. `VITE_` 를 붙이면 Vite 가 **빌드 시점에** 클라이언트 번들에 박아 넣는 전혀 다른
경로가 되고, 지금 코드는 그 자리를 읽지 않습니다.

> **카카오 키는 어차피 브라우저에 노출됩니다.** 지도 SDK 를 브라우저가 불러야 하니
> 숨길 수 있는 값이 아닙니다. 보호 장치는 **카카오 개발자 콘솔의 도메인 등록**입니다
> (3-4). 반대로 `API_BASE_URL` 은 브라우저로
> 내려가지 않습니다.

## 3. Vercel 배포 (정본)

### 3-1. 프로젝트를 만든다

1. Vercel 에서 **New Project** → 이 저장소(`mamoki-contest/tour_contest`)를 가져옵니다.
2. **Root Directory 를 `frontend` 로 지정합니다.** 저장소 루트가 아닙니다. 이 설정이 없으면
   Vercel 이 루트에서 `package.json` 을 못 찾고 빌드가 서지 않습니다.
3. **Framework Preset 이 `React Router` 로 잡혔는지 눈으로 확인합니다.**
   Vercel 은 `vite.config.ts` 안의 `@react-router/dev/vite` 와 `react-router.config.ts` 의
   존재로 프레임워크를 알아냅니다 — 둘 다 이 앱에 있습니다. 그래도 Root Directory 를 바꾼
   뒤 화면이 갱신되는지 **확인하세요.** `Other` 나 `Vite` 로 잡혀 있으면 손으로 골라 줍니다.
4. Build Command·Output Directory·Install Command 는 **건드리지 않습니다.** 자동으로
   `react-router build` / `build` / `npm install` 이 잡힙니다.
5. **Node.js Version 은 24.x**(기본값)로 둡니다. React Router 8 은 Node 22.22 이상을
   요구하므로 **20.x 를 고르면 안 됩니다.** `frontend/Dockerfile` 도 Node 24 라 맞아떨어집니다.

`vercel.json` 은 필요 없습니다. 이 저장소에 없고, 없는 채로 맞습니다.

### 3-2. 환경 변수를 넣는다

Project Settings → Environment Variables 에서 **Production 과 Preview 양쪽에** 넣습니다.

| 이름 | 값 |
| --- | --- |
| `API_BASE_URL` | `http://211.233.201.61:8080` (백엔드 주소가 바뀌면 그 주소) |
| `KAKAO_MAP_APP_KEY` | 카카오 개발자 콘솔의 **JavaScript 키** |

- **접두사 없이** 그대로 넣습니다(1절).
- **환경 변수를 고친 뒤에는 다시 배포해야 반영됩니다.** 이미 올라간 배포는 바뀌지 않습니다.
- `API_BASE_URL` 은 요청마다 서버에서 읽으므로 값이 바뀌면 다음 요청부터 듣습니다 —
  다만 Vercel 이 값을 함수에 넘기는 시점이 배포라, 결국 재배포가 필요합니다.

### 3-3. 빌드 로그에 나오는 경고 하나 — 고치지 마세요

```
WARN: The `vercelPreset()` Preset was not detected.
```

**이건 오류가 아닙니다.** `@vercel/react-router` 라는 선택 패키지를 쓰지 않아서 나오는
안내이고, Vercel 은 그다음 줄에서 `build/server/index.js` 를 찾아 서버 함수 하나로 감싸
정상적으로 배포합니다. 로그가 빨갛게 보인다고 이 자리를 손대면 오히려 일이 커집니다
(3-6 참고).

### 3-4. 카카오 콘솔에 배포 도메인을 등록한다

배포가 끝나고 주소가 나와야 할 수 있는 단계라 여기에 둡니다. **이걸 빠뜨리면 배포는
성공했는데 지도만 안 뜹니다.**

카카오 개발자 콘솔 → 내 애플리케이션 → **플랫폼 > Web > 사이트 도메인** 에 더합니다.

| 더할 주소 | 왜 |
| --- | --- |
| `https://<프로젝트>.vercel.app` | Production |
| 커스텀 도메인을 붙였다면 그 주소도 | Production |
| Preview 도메인 | PR 미리보기에서 지도를 보려면. Preview 는 배포마다 주소가 바뀌므로, 미리보기에서 지도를 확인할 일이 없다면 건너뛰어도 됩니다 |

지금 등록돼 있는 것은 로컬 개발 주소뿐입니다 — `localhost:5173` · `5174` · `5177`.
**이걸 지우지 마세요.** 로컬에서 `npm run dev` 로 확인할 때 필요합니다.

### 3-5. 백엔드의 `CORS_ALLOWED_ORIGINS`

**지금 프론트 동작에는 필요 없습니다**(0절). 그래도 백엔드 `.env.docker` 의
`CORS_ALLOWED_ORIGINS` 에 배포 주소를 넣어 두기를 권합니다.

```
CORS_ALLOWED_ORIGINS=https://<프로젝트>.vercel.app
```

이유는 하나입니다 — 나중에 브라우저에서 직접 부르는 경로가 생겼을 때, 이 값이 비어 있으면
원인을 CORS 라고 짐작하기까지 시간이 걸립니다. 넣는 데 드는 비용이 거의 없습니다.
반영은 백엔드 런북의 재배포 체크리스트 마지막 단계(앱 컨테이너만 `--force-recreate`)입니다.

### 3-6. 필요할 때만 추가할 것 (지금은 필요하지 않습니다)

**코드는 바꾸지 마세요.** 아래는 나중에 아래 상황이 왔을 때 무엇을 보면 되는지만 적어 둔
것입니다. 지금 배포에는 하나도 필요 없습니다.

**`@vercel/react-router` 프리셋** — `react-router.config.ts` 에 `presets: [vercelPreset()]`
을 더하는 선택 패키지입니다. 라우트마다 메모리·실행 시간을 따로 주거나, 라우트를 여러
함수로 쪼개거나, 엣지 런타임을 쓸 때 필요합니다.

> **지금은 넣을 수 없습니다.** 최신 `@vercel/react-router` 가 아직 React Router **7** 에
> peer dependency 를 걸고 있는데 이 앱은 **8** 입니다. 억지로 설치하면 의존성 해석이
> 깨지거나, 검증되지 않은 조합으로 돌게 됩니다. Vercel 이 v8 을 받는 버전을 낼 때
> 다시 보세요. 그전까지는 **프리셋 없이도 정상 배포됩니다**(3-3).

**`vercel.json`** — 필요 없습니다. Vercel 문서의 Vite 페이지에 나오는 SPA rewrite 설정은
클라이언트 전용 SPA 용이라 이 앱(SSR)에는 해당하지 않습니다.

**커스텀 `app/entry.server.tsx`** — 지금 없고, 없는 게 맞습니다. React Router 의 기본
엔트리가 쓰입니다.

> **알아 둘 것:** Vercel 의 React Router 문서·데모·변경 로그는 전부 **v7** 을 가리킵니다.
> v8 을 지원한다는 공식 발표를 찾지 못했습니다. 그럼에도 되는 이유는 Vercel 의 프레임워크
> 감지와 빌드 경로가 **버전을 보지 않고 파일 내용과 빌드 산출물 모양만 보기** 때문입니다.
> 즉 "되는 것을 확인한 것" 이지 "지원한다고 약속받은 것" 이 아닙니다. 첫 배포 뒤 4절의
> 체크리스트를 꼭 한 번 돌려 보세요.

## 4. 로컬과 같은지 확인하는 체크리스트

배포 직후 **이 순서로** 봅니다. 기대값은 2026-09-21 사용자 로컬(백엔드 도커 MySQL,
프론트 `npm run dev -- --port 5174`)에서 실제로 확인한 값입니다.

| # | 확인 | 기대 |
| --- | --- | --- |
| 1 | 홈(`/`) 이 열리고 목록 헤더의 개수 | **4,741곳** — 숫자가 다르면 백엔드 카탈로그 적재가 덜 된 것입니다 |
| 2 | 지도가 뜬다 | 회색 실패 자리가 아니라 실제 지도. 안 뜨면 `KAKAO_MAP_APP_KEY` 아니면 카카오 콘솔 도메인 등록(3-4) |
| 3 | 카드에 사진이 있다 | 전부 빈 자리면 **백엔드에서 `--job=place-image` 를 안 돌린 것**입니다. 프론트 문제가 아닙니다 |
| 4 | 정렬 전환 | `온라인 언급 많은 순` ↔ `온라인 언급 적은 순` 을 바꾸면 목록이 실제로 뒤집힌다 |
| 5 | 시·군 | 시·군 시트에서 하나 고르면 목록·지도가 그 시·군으로 좁혀진다 |
| 6 | 검색 3종 | ① 테마 칩을 직접 누름 ② 오타 검색(`해수용장`) → **`해수욕장 테마로 찾았어요`** 안내가 뜬다 ③ 자유 검색 → 큐레이션을 거치지 않았다는 안내가 뜬다 |
| 7 | 날짜 3상태 | ① **미정**(첫 진입) — 카드에 예측 배지가 **없다** ② `한산한 날에 갈래요`(FLEXIBLE) ③ 날짜 지정(FIXED). 미정에서 배지가 보이면 잘못된 것입니다 |
| 8 | 상세 — 강릉 경포대 | 주차가 **`AVAILABLE`**, 실시간 주차장(`강릉시 교통정보 조회서비스`)이 섞여 보인다. `정보 없음` 이면 백엔드의 주차 적재 또는 GNits 활용신청 문제 |
| 9 | 저장 | 카드/상세에서 저장 → `/saved` 에 뜬다 → 새로고침해도 남아 있다 (브라우저 `localStorage` 라 **기기·브라우저마다 따로**입니다) |
| 10 | 도움말 | 도움말 버튼 → 시트가 열리고, 뒤로가기로 한 겹 닫힌다 |
| 11 | 더 보기 | 목록 끝의 `더 보기` 가 20곳씩 늘리고, **100곳에서 끝 안내**가 뜬다 |

3·8번이 프론트가 아니라 **백엔드 적재** 문제라는 점을 기억하세요. 프론트를 다시 배포해도
고쳐지지 않습니다.

## 5. 대안 — 백엔드와 같은 서버에 Docker 로 띄우기

Vercel 을 쓰지 않기로 했다면 이 방법입니다. `frontend/Dockerfile` 이 이미 있습니다
(React Router 템플릿이 준 것으로, Node 24 로 빌드해 `npm start` 로 3000 포트에 띄웁니다).

**빌드 컨텍스트는 `frontend/` 입니다.**

```bash
cd frontend
docker build -t tour-frontend .
```

띄울 때 환경 변수를 넣습니다. **이미지에 굽지 마세요** — `API_BASE_URL` 과 카카오 키가
이미지에 박히면 값을 바꿀 때마다 다시 빌드해야 합니다.

```bash
docker run -d --name tour-frontend -p 3000:3000 \
  -e API_BASE_URL=http://211.233.201.61:8080 \
  -e KAKAO_MAP_APP_KEY=<카카오 JavaScript 키> \
  tour-frontend
```

> 값을 명령줄에 적으면 셸 히스토리와 `docker inspect` 에 남습니다. `--env-file` 로 파일을
> 넘기고 그 파일을 `chmod 600` 으로 잠그는 쪽이 낫습니다.

그다음:

- **NCP ACG 인바운드에 3000 을 엽니다.** 백엔드 8080 과 같은 방식입니다
  (`tour_backend` 런북 3-3).
- **카카오 콘솔에 `http://<서버IP>:3000` 을 등록합니다.** 포트까지 포함한 주소입니다.
- 같은 서버에 백엔드가 있으므로 `API_BASE_URL` 을 `http://211.233.201.61:8080` 그대로
  두면 됩니다. 컨테이너끼리 도커 네트워크로 잇고 싶다면 두 컨테이너를 같은 네트워크에
  넣고 백엔드 서비스 이름으로 부르면 되지만, 지금 백엔드 compose 와 분리돼 있어
  **공인 IP 로 두는 쪽이 단순합니다.**

**HTTPS 가 없습니다.** 이 방법으로 가면 사용자가 `http://` 로 접속하게 됩니다. 공모전
제출용으로는 지나갈 수 있지만, 그 상태로는 카카오를 포함한 일부 브라우저 기능이 제한될 수
있고 주소가 덜 미덥게 보입니다. HTTPS 가 필요하면 도메인을 붙이고 리버스 프록시(nginx +
Let's Encrypt)를 앞에 두거나, **Vercel 로 가세요.**

## 6. 알려진 미구현·한계

배포한 담당자가 "버그인가?" 하고 시간을 쓰지 않도록 적습니다. **전부 알고 둔 자리입니다.**

| 무엇 | 지금 상태 | 왜 |
| --- | --- | --- |
| **지도 마커 탭** | 마커를 눌러도 아무 일이 없습니다. 지도 이동·확대만 듣습니다 | 마커에 클릭 핸들러를 달지 않았습니다. 목록 카드로 상세에 들어갑니다 |
| **나만의 지도(저장 화면)의 마커** | `/saved` 는 **목록만** 입니다. 지도가 없습니다 | 와이어프레임에는 있지만 아직 구현 전입니다 |
| **시·군 방문 규모 색상 레이어** | 지도에 시·군을 색으로 칠하지 않습니다. 관광지 마커만 있습니다 | 행정구역 경계 데이터와 방문 규모가 **둘 다** 있어야 칠할 수 있습니다. 색을 지어내지 않고, 범례가 `방문 규모를 불러오지 못했어요` 로 그 사실을 말합니다 |
| **검색 결과에 혼잡 예측이 없다** | 목록에는 예측 배지가 붙는데 **검색 결과 카드에는 붙지 않습니다** | 백엔드 검색 엔드포인트가 `visitTiming` 을 `null` 로 돌려줍니다 (`tour_backend#98`). 프론트가 날짜를 보내도 마찬가지입니다 — 프론트에서 고칠 수 있는 자리가 아닙니다 |
| **`더 보기` 100곳 상한** | 20곳씩 다섯 번 늘리면 끝입니다 | 백엔드 한 번 조회의 최대 개수(100)가 정합니다. 화면이 끝에 도달했음을 안내합니다 |
| **저장이 기기에 묶인다** | 다른 기기·브라우저에서는 저장한 곳이 보이지 않습니다 | 회원가입을 MVP 범위에서 뺐습니다(ADR-0001). 브라우저 `localStorage` 에만 있습니다 |

## 막혔을 때

| 증상 | 확인 |
| --- | --- |
| 빌드가 `package.json` 을 못 찾는다 | Vercel 의 **Root Directory** 가 `frontend` 인지 (3-1) |
| Framework Preset 이 `Other`·`Vite` 로 잡혔다 | Root Directory 를 먼저 `frontend` 로 바꾸고, 그래도 아니면 손으로 `React Router` 를 고릅니다 |
| 빌드 로그에 `vercelPreset() Preset was not detected` | **정상입니다.** 고치지 마세요 (3-3) |
| 빌드가 Node 버전으로 실패한다 | Node.js Version 이 **24.x** 인지. React Router 8 은 Node 22.22 이상이 필요해 20.x 로는 안 됩니다 |
| 화면이 전부 "정보를 불러오지 못했어요" | `API_BASE_URL` 이 들어갔는지, **그리고 재배포했는지.** 환경 변수는 이미 올라간 배포에 소급되지 않습니다. 백엔드가 살아 있는지도: `curl http://211.233.201.61:8080/v3/api-docs` |
| 지도만 안 뜬다 | ① `KAKAO_MAP_APP_KEY` 가 비었는지 ② **카카오 콘솔에 배포 도메인이 등록됐는지**(3-4). 브라우저 콘솔에 카카오 SDK 오류가 찍힙니다 |
| 로컬에서는 지도가 뜨는데 배포에서만 안 뜬다 | 거의 항상 도메인 등록입니다. 로컬은 `localhost:5173/5174/5177` 이 이미 등록돼 있어서 뜹니다 |
| 카드에 사진이 하나도 없다 | **백엔드 문제입니다.** `--job=place-image` 를 안 돌렸습니다. `tour_backend` 런북 8-2-5 |
| 상세의 주차가 전부 `정보 없음` | **백엔드 문제입니다.** 주차장 표준데이터 적재 또는 강릉 GNits 활용신청 |
| 검색 결과에만 예측 배지가 없다 | 버그가 아닙니다. `tour_backend#98` (6절) |
| 저장한 곳이 다른 기기에서 안 보인다 | 사양입니다. `localStorage` 기반이라 기기·브라우저마다 따로입니다 (6절) |
